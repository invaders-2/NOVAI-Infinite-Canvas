## 一、本次报的 bug：文本节点连下游、下游识别不到

**根因**：画布连线有两种 `kind` —— 端口拖出来的是 `input`，「+」新建下游 / AI 助手 `connect` 落出来的是 `flow`；
而所有下游消费端（提示词识别、参考图、多维表格输入）走的 `inputNodesFor()` **只认 `input`**。
所以 flow 线画得出来、看着连上了，下游一律当没连。

**你那张真画布（140 节点 / 116 连线）实测**：

| | 修复前 | 修复后 |
|---|---|---|
| flow 边 61 条 → 下游识别到 | 0 条 | **61 条** |
| input 边 55 条 → 下游识别到 | 55 条 | 55 条 |

**改动**
- `static/js/smart-canvas.js`
  - `inputNodesFor()`：由 `['input']` 改为 `['input', 'flow']`（消费端统一认两种）
  - AI 助手 `connect` 默认 `kind` 由 `flow` 改为 `input`（新数据更规范）
- 新增回归测试 `tests/test_smart_canvas_input_edges.js`（9 项；把代码改回旧写法会挂 3 项）

## 三、拍我AI（pixverse）接入

**清单**：`default_models.video` +9 个（video/mimic/modify/multi-transition/restyle/swap/mask-selection/sound-effect/lipsync），`image` +pixverse-image-template。

**专属通路（实测契约）**
- 鉴权：代理要 `Authorization: Bearer`（文档写的 `API-KEY` 头会 401）
- `model` 必须传 pixverse 内部版本号（v6 等），传公共名会被 400
- 提交流程：图片/视频/音频先 `/openapi/v2/image|media/upload` 换 `img_id`/`media_id` → 生成 → 轮询 `GET /openapi/v2/video/result/{id}`（`Resp.url`，状态码文档未列枚举 → **有 url 即完成**）
- 已接：文生/图生/首尾帧（`pixverse-video` 按素材自动选路）、多帧、mimic、modify、restyle、sound-effect、lipsync（有音频用音频，否则用 TTS 音色+文本）
- 未接：`pixverse-swap`（要 mask_id）、`pixverse-mask-selection`（只返回 mask_id 中间产物）、`pixverse-image-template`（要 template_id）—— 选中会给出明确报错

**实测结果（真实 Key，走应用自身代码路径）**：sound-effect 970,892 B（12 credits）、restyle 3,663,969 B（60）、modify 814,963 B（48）、mimic 876,408 B（54）、lipsync 805,504 B（16）。
**踩坑并修掉**：① httpx 传字节必须用 `files=`（写成 `data=` 时上游报 “Either file or file_url must be provided”）；② pixverse 的 result 先给 url、文件随后才发布（刚拿到下载 404）→ 加了 pixverse 专属下载重试（5×10s）。
