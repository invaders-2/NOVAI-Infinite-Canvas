# 多维表格 → 视频分镜：逐段生成链路

> 状态：已实现并实测通过（2026-09）
> 前置：表格数据层见 `docs/v2/DXOS_TABLE_SPEC.md`；图片链路（同一套执行器）先落地，视频链路复用它。

## 1. 链路

```
参考素材（图片/视频，可多组）
        │
        ▼
     LLM 节点（输出模式 = 视频分镜表）
        │  ① 规划遍 FS：拆镜头、定 rowMode
        │  ② 生成遍 BS：出分镜表 JSON
        │  ③ 校验 a6 / 修复 CR（max_tokens 8192）
        ▼
     多维表格节点（每行 = 一个分镜）
        │
        ▼
     视频生成节点（批量生成 = 逐行逐段）
```

没有参考素材时同样成立：规划/生成提示词都显式允许「可用输入为（无）」，
直接依据用户提示词拆分镜，行数即镜头数。

## 2. 视频与图像的差异（只有三处）

| 点 | 图像 | 视频 |
|---|---|---|
| LLM 提示词 | 一行一张图的完整生成内容 | 一行一个分镜；必须含「时长(秒)」「运镜」「画面描述」三列 |
| 运行器 | `runGenerator` | `runVideoNode`（带 `rowOverride`） |
| 默认并发 | 3 | 1（视频又慢又贵，未显式设置时逐段串行） |

其余（表格数据层、输入通道、勾选语义、journal 续跑、失败策略、批量面板）完全共用。

## 3. 关键实现点

- **目标类型识别**：`llmDownstreamTarget()` 会穿过 `table` 节点继续往下看，
  所以 `LLM → 表格 → 视频` 也能识别成视频目标；链路还没接好时用输出模式
  「视频分镜表」（`llmOutputMode = 'list-video'`）显式指定，显式优先于探测。
- **按行覆盖**：`runTableBatch` 按节点类型派发运行器，把
  `{prompt, refs}` 作为 `rowOverride` 交给 `runVideoNode`；
  视频节点自己的模型/时长/比例/开关全部沿用，只有提示词与素材按行覆盖。
- **批量模式不弹窗**：`runVideoNode` 在 `opts.batch` 下用 `throw` 代替 `alert`，
  否则阻塞式对话框会把并发退化成串行。手动输入的视频网址在按行模式下不参与，
  否则它会盖掉每一行自己的素材。
- **每一列都进提示词**：`tableRowInputs` 把该行所有非空单元格按行拼成提示词，
  所以视频提示词里明确禁止模型创建「负向提示词/禁止项」列——那会被当成正向描述。

## 4. 验证

`tests/test_table_model.js` / `tests/test_table_node_dom.js` / `tests/test_table_node_wiring.js`
覆盖提示词内容、面板接线、运行器派发、并发默认值。

真实链路联调（`tests/test_video_storyboard_live.js`，直连正在跑的 `/api/canvas-llm`，不调用视频接口、不花钱）：

- 无参考素材：产出 8 列 × 4 行分镜表，逐行提示词无悬空引用。
- 参考角色图 ×3 + 白底产品图 ×2：规划遍给出
  `[{group:1,rowMode:'per-row'},{group:2,rowMode:'every-row'}]` → 通道模式 `['sequence','all']`，
  3 行 × 每行 3 个素材，逐行提示词无悬空引用。

## 5. 已知限制

- 分镜时长目前是提示词里的文字（表格「时长(秒)」列会拼进提示词），
  视频节点自身的 `duration` 仍是整批共用的 API 参数。要做到「每段时长不同」
  需要再引入按行覆盖 API 参数，目前不做。
- 表格同时接到图像节点和视频节点时，靠连接顺序取第一个；用显式「视频分镜表」可以定死。
