### 状态定义

| 状态 | 含义 |
|---|---|
| `PASS` | 验收项已完成，证据完整，未发现阻断问题。 |
| `FAIL` | 与预期不符、数据丢失、产生假结果，或存在阻断发布的问题。 |
| `BLOCKED` | 缺少 API Key、Provider 不可用等外部条件，不能伪装为通过。 |
| `N/A` | 本次版本明确未交付该 Phase；必须写明原因。 |
| `UI_ONLY` | 只有界面或接口壳，没有真实闭环；不得算通过。 |

### 证据要求

每个 `PASS` 至少附一种可复查证据：API 请求/响应、任务 ID、Provider 请求 ID、产物文件路径、Asset ID、画布或版本 ID、截图、日志、自动测试输出或 Git Commit。涉及生成的场景，必须记录真实 Provider 和模型。

|---|---|---|---|---|
| SMK-01 | 创建项目与画布 | 创建并打开一个智能画布；刷新后仍可打开。 | | |
| SMK-02 | 上传/选择参考素材 | 素材有稳定 Asset ID；节点引用该 ID 或可追溯的资产关系。 | | |
| SMK-03 | 发起真实生成 | 点击生成后创建真实任务，不直接由前端调用第三方 Provider。 | | |
| SMK-04 | 状态可观察 | 可看到任务由 `queued` 进入执行并最终收敛；失败时显示具体原因。 | | |
| SMK-05 | 真实产物 | 获得可打开的真实图片文件，非占位图/历史文件。 | | |

| ID | 验收项 | 通过标准 | 状态 | 证据 / 问题 |
|---|---|---|---|---|
| P1-08 | 网络失败 | 超时、断网或 Provider 5xx 显示明确原因；仅未提交上游的安全场景自动重试。 | | |
| P1-09 | 鉴权/限流 | 401、403、429 不被误标为成功；提示 Provider、下一步和是否可重试。 | | |

## 12. 缺陷分级与发布门禁

| 等级 | 定义 | 发布处理 |
|---|---|---|
| P0 | 数据丢失、密钥泄露、任意文件操作、错误计费、应用无法启动、核心生成假成功。 | 阻断发布。 |
| P1 | 主流程无法完成、重启丢任务/产物、Matrix 任务数错误、版本无法还原、严重回归。 | 阻断发布。 |
| P2 | 有明确绕过方式的功能错误、主要体验或性能问题。 | 原则上修复；如延期需书面接受风险。 |
| P3 | 文案、样式、非核心边界问题。 | 可带已知问题发布。 |

### 最终发布判定

- `可发布`：冒烟测试全通过；无 P0/P1；已交付 Phase 的必测项全部 `PASS`；自动测试结果可解释且无新增回归。
- `修复后复验`：无 P0，但有未关闭 P1 或关键 `BLOCKED`，或证据不足以证明真实闭环。
- `不可发布`：存在 P0，或任一核心闭环出现假成功、数据丢失、无法启动、错误扣费风险。
