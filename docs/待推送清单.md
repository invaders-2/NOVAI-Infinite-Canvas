## ⏳ 2026-11-14 · 画布助手「发了没反应」：SSE 被 gzip 憋住 + 默认开流式 + 心跳 2 秒

**状态**：本地改完，未提交、未 push、未重新打包。改动：`main.py`、新增 `tests/conftest.py`、新增 `tests/test_sse_not_gzipped.py`、`tests/test_agent_run_stream.py`、`tests/test_agent_stream_events.py`。

**现象**：用户反馈第一次用画布助手反应很慢、回复很慢，看不出助手在跑。

**根因（真机实测，不是猜）**
- **SSE 被 gzip 憋住**：starlette 0.41 的 `GZipMiddleware` 没有 event-stream 排除表（源码里没有，老注释写了「有」是错的）。浏览器带 `Accept-Encoding: gzip` 时，SSE 被 zlib 攒到缓冲区满才吐，`run_start`／心跳／逐字增量全憋到流结束。实测同一条请求：gzip 头下所有事件都在 3120ms 一起到；`identity` 下 `run_start` 56ms 就到。前端 SSE 主通道被这样堵住后，只剩 20s 一次的轮询兜底 → 用户看到的就是「一直没反应」。
- **默认非流式**：`NOVAI_AGENT_V2_STREAM` 默认关，模型不写完一个字都不显示。
- **心跳 5 秒**：面板「已 N 秒」推进太慢，且上面的 gzip 问题让它根本到不了。

**改动**
- `main.py`：用 `SSEExemptGZipMiddleware` 替换 `GZipMiddleware`——按响应 `Content-Type` 判断，`text/event-stream` 不压缩直出，其它文本照旧 gzip（小响应仍受 `minimum_size=1024` 保护）。
- `main.py`：`_agent_v2_stream_enabled()` 默认打开（`NOVAI_AGENT_V2_STREAM=0` 可退回老的非流式）；平台不支持流式由既有 TTL 名单自动回退，不用手动关。
- `main.py`：`_AGENT_HEARTBEAT_SECONDS` 5s → 2s。
- 测试：`tests/conftest.py` 把历史 producer 用例（非流式行为快照）统一钉在 `NOVAI_AGENT_V2_STREAM=0`；`tests/test_sse_not_gzipped.py` 守「SSE 不压缩 / 普通 JSON 仍压缩 / 默认开流式 / 心跳 2s」。

**真机实测（macOS 本机真后端 + 真实 APIMart key，隔离数据目录）**

                              message_delta=3668ms，done=3885ms

## ⏳ 2026-11-14 · 托盘退出后后端进程仍在（任务管理器还挂着 NOVAI.exe）

**状态**：本地改完，未提交、未 push、未重新打包。改动：`desktop/main.js`、`main.py`、`launcher.py`、`tests/test_desktop_win_update.js`（同步新断言）、新增 `tests/test_desktop_backend_quit.js`。

**现象**：Windows 上从系统托盘右键「退出 NOVAI」，窗口关了，但任务管理器里还能看到 NOVAI.exe（Python/后端那个）一直在跑；再启动又「复用」它，于是永远关不干净。

**根因（两条都成立，按证据分开修）**
- Electron 版：退出时用的 `spawn('taskkill')` 是异步的，壳可能先走完退出，杀进程的时机全靠运气；更关键的是「复用 3000 上已有后端」时 `backendProc` 为空，退出钩子直接 return 不杀 —— 一旦上一次留下过一个残留，之后每轮都在复用它、每次退出都不管它。
- 传统安装版（pywebview）：托盘「退出 NOVAI」在 pystray 线程里跨线程 `wins[0].destroy()`，抛错或卡住时 `webview.start()` 永不返回，进程就一直挂着（JS 侧的 `quit_app` 早就是 `os._exit(0)`，只有托盘这条漏了）。

**改动**
- `desktop/main.js`：`killProcessTree()` 统一用 `spawnSync('taskkill','/F','/T','/PID')`，退出钩子里同步杀完整棵树；`shutdownBackend()` 幂等（`before-quit` + `will-quit` 都走）；spawn 后端时把 pid 记到 `<userData>/backend.pid`，杀成功才删；启动时 `cleanupStaleBackend()` 先收拾自己上一轮的残留（要求 pid 记录 = 该端口监听者 = 该端口确实是 NOVAI 后端，三条都成立才动手，避免误杀用户自己起的服务）；`before-quit` 里每个动作单独 try，避免某一步抛错把「杀后端」这一步跳过。
- `main.py`：新增 `_start_parent_watchdog()`，壳通过 `NOVAI_PARENT_PID` 传自己的 pid；Windows 用 `OpenProcess(SYNCHRONIZE) + WaitForSingleObject` 等壳退出（PID 被复用也不误判），其它平台轮询 `os.kill(pid,0)`；壳一没就 `os._exit(0)`。直接 `python main.py` / 传统安装版不传这个变量，行为不变。
- `launcher.py`：托盘 `on_quit` 先起 2s 强制退出兜底，`finally` 里 `os._exit(0)`，卡在 `destroy()` 也一定会退出。
