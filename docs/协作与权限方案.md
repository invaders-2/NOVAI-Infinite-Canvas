# NOVAI 协作与权限方案（计划稿）

> 目标：混合模式（客户端本地能力 + 云端账号/模型/图床/协作），单个画布最多 10 人实时协作。
> 本文只是计划，不动代码；配套交互预览见 artifact「NOVAI 协作画布 · 交互预览」。

## 1. 总体架构

```
┌─────────────── 客户端（Electron 安装包）───────────────┐
│ 渲染层（远程 Web UI 或本地 UI）                          │
│ 本地后端（FastAPI 精简）：ComfyUI 代理 / 本地文件 / 本地模型 │
└───────────────┬──────────────────────────────────────┘
                │ HTTPS + WebSocket（登录态）
┌───────────────▼───────────── 云端 ─────────────────────┐
│ API（FastAPI）：账号/邀请码/画布元数据/权限/图床/模型代理   │
│ 协作服务（Node + Yjs）：WebSocket 房间、presence、光标     │
│ 存储：SQLite/Postgres + 素材目录（本地盘或 OSS）+ Redis     │
│ 上游：APIMart（团队）/ 国产模型（公开用户预留）              │
└────────────────────────────────────────────────────────┘
```

- 客户端保留本地小后端，只做**离不开本机**的能力（ComfyUI、本地文件、本地模型），其余全部走云端。
- 云端持有所有 key、账号、素材；客户端不落任何密钥。
- 图床：参考图上传 → 云端签名 URL 给 APIMart；生成结果**立即下载落盘**（上游链接会过期）。

## 2. 实时协作

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 服务端广播操作 | 简单 | 冲突多、断线难恢复 | 不推荐 |
| OT | 成熟 | 实现复杂、服务端重 | 不推荐 |
| CRDT（Yjs） | 冲突自动合并、离线友好、生态成熟 | 需要独立协作服务 | **推荐** |

- 协作服务独立于 Python 后端：Node + Yjs（y-websocket），画布文档 = 节点图（节点/连线/属性/视口）。
- 持久化：Yjs update 日志 + 每 N 分钟快照；服务端可回放。
- 房间准入：WebSocket 握手校验画布权限；**每房间上限 10 人**，超出返回排队状态。
- Presence：光标 30–50ms 节流；颜色按成员分配；心跳 10s，30s 无心跳移除；在线列表广播。
- 断线：本地缓存 pending 操作，重连后合并；版本号 + 全量快照兜底。

## 3. 权限模型

| 角色 | 查看 | 编辑画布 | 邀请成员 | 改权限/删除 | 转移所有权 |
|---|---|---|---|---|---|
| 创建者 owner | ✓ | ✓ | ✓ | ✓ | ✓ |
| 管理员 admin | ✓ | ✓ | ✓ | 部分 | ✗ |
| 可编辑 editor | ✓ | ✓ | 可选 | ✗ | ✗ |
| 仅查看 viewer | ✓ | ✗ | ✗ | ✗ | ✗ |

- 分享：公开链接 / 密码链接 / 有效期 / 仅受邀；链接默认“仅查看”，可切换“可编辑”。
- 部门共享：画布可共享给部门，部门成员按角色继承。
- 所有权限变更写审计日志（谁、何时、把谁改成什么）。

## 4. 组织与社交

- 组织（workspace）→ 部门 → 成员；角色：组织管理员 / 部门管理员 / 成员。
- 好友：申请、同意、删除、黑名单；好友可被邀请协作、可看公开作品。
- 社区：发布画布/模板、克隆、点赞、评论；**UGC 需要审核**（敏感词 + 图片检测 + 举报 + 人工复审），这是公开运营的前置条件。

## 5. 数据模型（核心表）

users、workspaces、departments、memberships、friendships、canvases、canvas_members、canvas_shares、canvas_snapshots、comments、community_posts、assets、sessions、audit_logs。

## 6. 接口草案

- REST：/api/auth/*、/api/canvases、/api/canvases/{id}/members、/api/canvases/{id}/share、/api/friends、/api/departments、/api/community、/api/assets/upload
- WS：/ws/canvas/{id}?token=…；事件：join/leave、presence、cursor、op、snapshot、permission
- 图床：POST /api/assets/upload → {url, thumb, expires}；GET /assets/... 签名校验

## 7. 里程碑

| 阶段 | 内容 | 预估 |
|---|---|---|
| M1 | 账号 + 邀请码 + 登录（已有半成品，暂停中） | 2–3 天 |
| M2 | 云端后端 + 图床 + 客户端混合改造 | 1–2 周 |
| M3 | 画布权限 + 分享 + 成员管理 | 1 周 |

| M5 | 社区 + 好友 + 部门 | 2 周 |
| M6 | 内容审核 + 运营/合规 | 1–2 周 |

## 8. 风险

1. **双后端复杂度**：客户端本地后端 + 云端后端，接口边界要一开始定死，否则后面互相污染。
2. **CRDT 成本**：Yjs 需要独立 Node 服务与 Python 后端并行，部署和鉴权要打通。
3. **性能**：10 人同时拖拽 + 大量图片节点，需要虚拟化/缩略图/操作节流。
4. **UGC 合规**：社区一旦对外开放，审核和举报必须同步上线。
5. **图床成本**：素材流量和磁盘是长期成本，需备份与清理策略。
6. **10 人限制**：服务端房间准入 + 前端排队提示，避免“第 11 人”静默失败。
